## 1. 插件定义与目录结构

插件是一个目录,目录名必须与 manifest 的 `id` 一致:

```
my_plugin/
├── plugin.json        # 必需,manifest
├── backend.py         # 必需,后端入口(可在 manifest 的 entry 字段改名)
├── migrations/        # 可选,数据库迁移
│   ├── 001_init.sql
│   └── 002_xxx.sql
└── web/               # 可选,前端资源
    └── my-panel.js
```

插件来源两处,协议完全相同:

- **内置**:`plugins/`(随应用打包);
- **第三方**:`<用户数据目录>/plugins/`(用户手动放置)。

id 冲突时内置优先,第三方插件被跳过并记日志。第三方插件本期处于"待启用"状态,不自动加载(启用流程在后续版本提供)。

## 2. manifest(`plugin.json`)

| 字段 | 必需 | 说明 |
|---|---|---|
| `id` | ✓ | 全局唯一,小写字母/数字/下划线;同时是路由、表、配置、前端的命名空间前缀 |
| `name` | ✓ | 显示名 |
| `version` | ✓ | 插件自身版本,语义化版本 |
| `api_version` | ✓ | 面向的内核 API 版本,当前为 1 |
| `entry` | ✓ | 后端入口文件名,通常 `backend.py` |
| `dependencies` | | 硬依赖 id 列表,缺失则本插件不加载 |
| `optional_dependencies` | | 有则排在其后加载,无则跳过 |
| `web` | | 前端资源文件列表(相对插件目录),按依赖顺序排列 |
| `legacy_routes` | | **迁移期逃生门,第三方插件禁止使用**;为 true 时允许注册任意路径(做冲突检测) |
| `min_core_version` | | 预留,暂未校验 |

## 3. 后端入口与生命周期

`backend.py` 导出 `Plugin` 类(或 `create_plugin()` 工厂),全部方法可选:

```python
class Plugin:
    def activate(self, api):
        # 注册路由、订阅事件、声明服务
        ...
```

加载流程:扫描 → manifest 校验 → 拓扑排序(dependencies / optional_dependencies)→ 每插件依次:执行未应用的迁移 → 加载 entry → 实例化 → `activate(api)`。任何插件失败不影响其他插件(故障隔离,失败原因记日志)。

**禁止事项**:

- 禁止 import 其他插件的内部模块,插件间只允许通过 `api.provide` / `api.require` 交互;
- 第三方插件只能依赖 Python 标准库和 `api` 暴露的能力(发行版未打包的三方包在打包环境中不存在)。

## 4. PluginAPI(`activate(api)` 拿到的对象)

> 本节是协议的核心表面,v1.0 冻结前方法签名可能调整。

### HTTP

- `api.route(rule, **opts)` — 注册路由,等价 Flask 的 route 装饰器。路径必须以 `/api/plugins/<id>/` 开头,违反则插件加载失败。`opts` 支持 `methods=["POST"]` 等。
- 请求处理相关透出:`api.request`、`api.jsonify`、`api.req_json()`(取 JSON body)、`api.snake_json()`(camelCase → snake_case 转换)、`api.convert_keys()`。

### 数据

- `api.db()` — 返回新 SQLite 连接,用法 `conn = api.db(); ...; conn.close()`。WAL 模式,无需自行加锁。
- helper 透出:`api.row_to_dict`、`api.soft_delete`、`api.restore_soft_delete`、`api.next_sort_order`、`api.hash_content`、`api.count_words`。
- `api.data_dir` — 用户数据目录路径(与数据库同侧)。

### 配置

- `api.get_config(key, default=None)` — 读取配置。正常只读 `<id>.` 前缀的自有键。
- `api.set_config(key, value)` — 写入配置,键**强制** `<id>.` 前缀,违反抛错。
- 存储为字符串;内核配置 UI 后续版本提供。

### 事件

- `api.on(event, handler)` / `api.emit(event, **payload)` — 后端事件总线。
- 事件名约定 `<plugin_id>.<动作>`,如 `chapter.deleted`。内核保证发出的事件目录见 §6。

### 服务注册表

- `api.provide(name, service_dict)` — 声明本插件对外提供的公开函数。
- `api.require(name)` → `dict | None` — 消费其他插件的服务,缺失返回 `None`(消费硬依赖的服务前仍应判空,防御性)。
- **约定:在请求处理时调用 `api.require()` 取用,不要在 `activate()` 里缓存结果**——规避加载顺序耦合;对端缺失时路由应返回 503。

## 5. 命名空间硬约束(加载器强制)

| 资源 | 约束 | 示例(id 为 `chapter`) |
|---|---|---|
| 路由路径 | `/api/plugins/<id>/` 前缀 | `/api/plugins/chapter/list` |
| 配置键 | `<id>.` 前缀 | `chapter.autoSaveInterval` |
| 数据库表 | 约定 `<id>__` 前缀(当前版本未强制,v1.0 计划强制) | `chapter__chapters` |
| 前端全局 | 只允许挂在 `NW.plugins.<id>` 下 | `NW.plugins.chapter` |

## 6. 事件目录

当前内核不主动发出业务事件(事件总线已就位,事件目录随业务插件迁移逐步补充,见设计文档 §4)。v1.0 将包含内核保证的事件清单及 payload 结构。

## 7. 前端

- manifest 的 `web` 列表中的脚本由内核按插件加载顺序自动注入页面,无需也不应自行写 `<script>` 标签;
- 脚本可用全局:`NW`(内核命名空间)、`AppState`(含 `on`/`emit` 事件总线)、`api`(HTTP 封装);
- 插件前端代码挂到 `NW.plugins.<id>`;扩展点通过 `NW.registerComponent(extPoint, component)` 注册、`NW.getComponents(extPoint)` 消费;
- **一个插件多个 web 文件时**:主组件挂 `NW.plugins.<id>`,辅助模块挂子键 `NW.plugins.<id>.xxx`(挂子键前用 `|| {}` 防御);
- **初始化时序**:插件脚本由引导器动态加载,加载时 `DOMContentLoaded` 通常已过——初始化代码必须判断 `document.readyState` 直接执行,**不要依赖 `DOMContentLoaded` 监听**(永远不会触发);
- **迁移期兼容别名**:文件末尾保留 `window.原全局名 = NW.plugins.<id>`(双写 const 词法绑定 + window 属性),供未迁移的旧代码全局引用;别名在阶段 5 统一拆除;
- 扩展点清单(sidebar / editor.toolbar / settings 等)在设计文档 §7.4,**尚未实现**,v1.0 定稿;
- 脚本加载失败不会阻塞应用其余部分启动。

## 8. 数据库迁移

- 插件的表结构演进放在 `migrations/NNN_描述.sql`,NNN 为三位序号,按序执行,每插件独立序列;
- 执行记录在内核元表 `plugin_migrations`,已应用的不会重复执行;
- **SQL 必须幂等**(`CREATE TABLE IF NOT EXISTS` 等),迁移在事务中执行,失败则插件加载失败;
- 插件只许动自己的表。

## 9. 版本与废弃策略(v1.0 起生效,草案)

- 内核 API 语义化版本;`api_version` 只增不减;
- 废弃的方法/字段至少保留一个大版本,并在 changelog 标注"自 vX 起废弃,计划 vY 移除";
- 每次内核发版同步更新本文件的 changelog 节。

## 10. 安全模型(如实告知)

插件与应用同进程运行,**拥有完整权限**(读写数据库、文件系统、网络),没有沙箱。不要安装来源不明的插件。第三方插件默认不启用,需用户显式操作。
